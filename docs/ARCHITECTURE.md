# 架構

桌寵（Godot 4.7 .NET，`godot/src/`）和網頁預覽／編輯器（原生 JS，`preview/js/`）共用同一份資料（`art/`、`data/`），各自實作同一套動畫與規則。這份文件說明程式怎麼分層、功能怎麼做成模組、資料放哪裡、兩邊怎麼保持一致。

升級計畫見 [plan_doc/UPGRADE_PLAN.md](../plan_doc/UPGRADE_PLAN.md)。

## 分層

由下往上，**上層可以引用下層，下層不引用上層**：

| 層 | Godot（`godot/src/`） | 網頁（`preview/js/`） | 放什麼 | 不可以 |
|---|---|---|---|---|
| 資料 | `Content/` | `core/loader.js` | 資料格式（`Models.cs`）、讀取、翻譯、台詞 | 引用其他層 |
| 計算 | `Core/` | `core/` | 純計算：骨架、動畫器、之後的物理、網格、聲音分析 | 建立 Godot 節點、讀檔、碰視窗；可以用 Godot 的數學型別（`Vector2`、`Transform2D`） |
| 規則 | `Game/` | `game/` | 角色狀態與行為、互動規則、小遊戲規則、收集系統、客人角色 | 直接操作視窗或系統 API（透過 `Platform`） |
| 畫面 | `View/` | `view/` | 把狀態畫出來：角色部件、特效、泡泡、球、聲波 | 改變規則狀態 |
| 介面 | `UI/` | `ui/` | 系統匣、右鍵選單、Desk Pet 視窗各分頁 | 自己保存遊戲狀態（交給 `Game`／`Save`） |
| 系統整合 | `Platform/` | （沒有） | Windows API：透明視窗、點擊穿透、全域鍵盤、視窗走訪、音量表、開機啟動；`Platform/Live/` 外部服務（Twitch、Discord） | 引用 `Game`、`View`、`UI`（例外見下） |
| 存檔 | `Save/` | localStorage | 設定與進度的讀寫 | 引用其他層 |
| 音訊 | `Audio/` | （沒有） | 合成音效、撥弦、音樂播放 | 引用 `Game` 以上 |
| 串接 | `Main*.cs` | `main.js`、`gallery.js` | 建立各層物件、接事件、主迴圈 | 放規則或計算（要往下搬） |

### 目前的例外（逐步修正）

| 例外 | 原因 | 修正時機 |
|---|---|---|
| `Game/Pet.cs` 建立並持有 `View/PetView` | 移植網頁版時角色與畫面寫在一起 | 0r（角色本體和驅動方式分開）、0u（掛件跟著錨點） |
| `Game/Guests/Guest.cs`、`Game/Volley/VolleySession.cs` 建立節點（泡泡、特效、名牌、球） | 同上 | 0u |
| `Platform/Live/*` 引用 `Game.Guests.PresenceEvent` | 事件格式放在 `Game` | 把 `PresenceEvent`、`PresenceSource` 搬到中立的位置（`Content` 或新的 `Signals`），做 0t 時一起處理 |
| `Platform/Live/DiscordRpc.cs` 引用 `Save.Settings` | 建構時直接讀設定 | 0v（設定依功能分段）時改成傳入需要的值 |
| `View/SpeechWaves.cs` 寫死嘴巴座標 | 還沒有臉部錨點 | 0p、3h |

新程式**不可以增加例外**；碰到需要跨層時，先想能不能用事件或介面反過來。

## 功能模組

功能（專注、音樂、日常、收集、自訂內容、多人，之後的半身模式）現在是 `Main` 的 `partial` 檔，共用 `Main` 的欄位。目標是每個功能一個資料夾 `godot/src/Features/<功能>/`，實作 `IFeature`（0k）：

| 介面要提供的 | 用途 |
|---|---|
| 初始化（拿到共用服務：角色、行為、設定、系統匣、Hub…） | 不再直接讀 `Main` 的欄位 |
| 主迴圈分段：行為之前、行為之後（`Pet.Update` 之前）、畫面之後 | 例如動嘴（`Mouth`）一定要在 `behavior.Update` 之後、`pet.Update` 之前 |
| 滑鼠：點擊判定、要不要接收滑鼠（點擊穿透）、拖曳 | 例如客人角色可以被點、被拖 |
| 隱藏／顯示、螢幕縮放變化 | 例如全螢幕自動隱藏時客人也要隱藏 |
| 系統匣、右鍵選單、Hub 分頁的項目 | 不再改 `Tray.cs`、`HubWindow.cs` 的固定清單 |
| 存檔、結束 | 各自管理自己的設定段（0v） |

規則：

- **隨功能搬**：動到哪個舊功能才把它搬成模組，**搬家和改功能分兩個 commit**，搬完手動跑過一遍
- 功能之間不直接互相引用；要合作就透過共用服務（例如「誰在控制角色」的仲裁，0q）

## 資料放哪裡

| 資料 | 位置 | 誰產生 |
|---|---|---|
| 角色（骨架、插槽、部件、表情、型態） | `art/characters/<id>/` | `tools/gen_art.py`（佔位角色）、之後的匯入工具（第 5 階段）。**不手改** |
| 道具、配件 | `art/props/`、`art/accessories/` | `tools/gen_art.py` |
| 動作 | `data/animations/`（體型專屬在子資料夾） | 手寫或之後的動作編輯器 |
| 規則與參數 | `data/*.json`（互動、選單、日常、專注、收集、排球、音樂、客人…） | 手寫 |
| 翻譯 | `data/i18n/` | `tools/i18n/build.py` 與手寫 |
| 使用者自訂內容 | `文件\DeskPet\`（配件、衣服、角色、音樂） | 使用者、自訂編輯器 |
| 使用者設定與進度 | `user://settings.json`、`user://progress.json` | 程式 |
| 打包用的資料複本 | `godot/content/`（不進 git） | `tools/sync_content.py` |

規則：

- **參數放 `data/`，不寫在程式裡**；兩邊讀同一份
- **角色的座標放角色資料**（錨點），不寫在程式裡
- 新欄位一律**選配**，沒有的時候照舊運作；舊格式讀進來要能自動轉換

## 兩邊同步

| 要同步 | 不用同步（Godot 專屬） |
|---|---|
| 資料格式與讀取、骨架、動畫器、行為規則、排球、收集系統、繪製結果，之後的物理、網格、聲音分析 | `Platform/`（透明視窗、點擊穿透、全域鍵盤、視窗平台、音量表）、`Platform/Live/`（Twitch、Discord）、系統匣、開機啟動、客人角色 |

- 同一個功能**兩邊都做完、共用測試（`tests/golden/`，0h）都通過**才算完成
- 共用測試只測**確定的計算**；數值比對有容許誤差；有隨機的行為邏輯不放進來

## 新增功能的檢查清單

1. 屬於哪一層？會不會增加跨層的例外？
2. 參數放進 `data/` 了嗎？角色相關的座標放進角色資料了嗎？
3. 新欄位是選配嗎？舊角色、自訂角色、四足型態照舊運作嗎？
4. 是功能模組（`Features/`）嗎？需要哪些主迴圈分段、滑鼠、隱藏的掛勾？
5. 網頁要不要同步？要的話共用測試加了嗎？
6. 有沒有加測試參數（`--test=…`、`--selftest=…`、假資料來源）方便不用手動就能驗證？
7. 翻譯（`data/i18n/` 三種語言）加了嗎？
8. README 的功能表、`plan_doc/` 有沒有更新？
