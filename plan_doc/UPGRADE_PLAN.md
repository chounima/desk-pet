# 動畫、美術與半身模式升級規劃

2026-11-04 起草，同日依討論修訂。2026-11-07 依程式現況校對，加入「美術來源不限（AI 輔助／純人工）」、「半身 VTuber 模式」，並依決定調整順序：**先把部件包流程做好、用 AI 產出全部角色**，再做動作系統；半身模式放最後；第 0 階段加入「預留與解耦」。

目標：
1. 動作像專業桌寵一樣流暢（頭髮、尾巴、衣服自然飄動、身體有彈性、表情細膩）
2. **美術和程式完全分開**：不管是純人工手繪，還是 AI 輔助產生再修，只要照同一份規格交出「部件包」，就能直接套用，畫師不用碰程式
3. **半身 VTuber 模式**：放大顯示上半身，跟著使用者的聲音動嘴、依音量和音調換表情或做動作，眼睛跟著游標

## 已定案

| 項目 | 決定 |
|---|---|
| 升級路線 | 在現有系統上自己加（物理、曲線、網格變形），不換 Live2D／Spine |
| 程式碼 | 升級前先整理**必要的部分**（參數、格式、共用測試）；功能模組化改成「做到哪個功能就順便搬」（2026-11-07） |
| 網頁預覽 | 動畫、繪製、資料格式、聲音分析**都和 Godot 同步**，包含網格變形（網頁改用 PixiJS 繪製）；`Platform/`、`Platform/Live/`（視窗、Twitch、Discord、偵測音量）是 Godot 專屬，不用同步 |
| 手機版 | **先不做**（響應式、觸控、PWA、手機存檔都延後） |
| 動作編輯器 | 要做，放在動作系統升級之後、重修動作之前 |
| 角色專屬動作 | 動作依「角色＋型態 → 角色 → 體型 → 共用」往上找；角色專屬可以只寫差異 |
| 美術 | 和程式分離：原始檔放 `art_src/`，綁骨在編輯器裡做，正式角色和自訂角色用同一種格式 |
| 美術來源（2026-11-07） | **不限**：純人工、AI 輔助、混合都可以。程式只認「部件包」規格，不管圖是怎麼來的；來源與工具記錄在 `CREDITS.md` |
| 美術做法（2026-11-07） | **先用 AI 把全部角色快速做出來**，之後需要再人工精修。所以部件包流程（第 5 階段前段）提前到第 0 階段之後；部件規格**一次要求齊**之後功能會用到的部件（分層臉、頭髮分節、關節重疊、正面半身），避免之後全部重產 |
| 半身模式（2026-11-07） | 要做，**放在最後**：聲音 → 動嘴、表情、動作；眼睛跟游標。**在桌面上看**，顯示在現有的桌面透明視窗裡；直播時直接擷取整個桌面畫面，不另外做 OBS 專用視窗或綠幕 |
| 預留與解耦（2026-11-07） | 只預留**已經規劃好的功能**會用到的接縫（角色格式欄位、動作與表情的優先順序、驅動方式、觸發規則格式、自己的聲音、取景、設定分段），在第 0 階段做；不做通用外掛系統、依賴注入、萬用事件匯流排 |

## 結論：做得到，而且不用打掉重來

| 現況 | 為什麼適合升級 |
|---|---|
| 骨架、插槽、部件都是資料（`rig.json`、`data/animations/*.json`） | 新功能可以做成「選配欄位」，舊角色、自訂角色不用改 |
| 畫面集中在 `PetView`（Godot）和 `renderer.js`（網頁） | 換繪製方式（例如網格變形）只動這一層 |
| 姿勢流程是一條線：`Animator.Update` → `Gaze` → `Skeleton.Compute` → `PetView.Render` | 物理和疊加動作可以插在 `Skeleton.Compute` 前後，不用動行為邏輯 |
| 已經支援 PNG 部件與 `character.json`（自訂角色、衣服） | 手繪或 AI 產生的美術與正式角色可以沿用同一條讀取路徑 |
| 已經有選配骨頭（`tail`、`cape`、`back`）與體型動作組（`quadruped/index.json` 的 `clips`、`alias`） | 頭髮骨鏈、角色專屬動作都是同一個模式的延伸 |
| SVG 執行時依顯示大小轉貼圖，貼圖全域快取共用（`SvgTextures.Cache`） | 半身模式放大好幾倍也清楚；多隻客人共用同一份貼圖 |
| 已經有 `Mouth`（講話動嘴）、`SpeechWaves`（聲波）、`Gaze`（看游標）、`AudioWatch`（麥克風音量） | 半身模式的動嘴、看游標、聲音觸發都有雛形，要做的是升級成「依聲音細節驅動」 |

## 跟流暢桌寵的差距

| 項目 | 現況 | 差距 |
|---|---|---|
| 插值 | 每段都用 smoothstep（`Animator.SampleTrack`） | 沒有彈回、預備、停頓、線性這些選擇，動作看起來都一樣「軟」 |
| 次級動作 | 尾巴、披布寫死在關鍵影格（`walk.json` 的 `tail`、`cape`） | 停下來、被拖曳、落地時不會甩 |
| 頭髮 | `hair_front`、`hair_back` 黏在 `head` 上，是整片硬圖 | 不會飄 |
| 部件 | Sprite2D／SVG 硬紙片，只能轉、移 | 關節會折出硬角，身體不能彎 |
| 骨骼 | 只有角度與位移，**沒有縮放** | 做不出 squash & stretch |
| 待機 | `idle` 一個循環＋眨眼 | 沒有呼吸、重心晃動 |
| 表情 | 整張臉一張 SVG，直接換圖；動嘴是「驚訝／開心」兩張臉交替（`Mouth.cs`） | 眼睛、嘴、眉毛不能分開組合；嘴型沒有母音；**角色自己冒台詞泡泡時不會動嘴**（Discord／麥克風講話時才會） |
| 視線 | `Gaze` 讓整張臉位移一點、頭轉一點 | 瞳孔不會自己動；沒有前後圖層的視差立體感 |
| 動作製作 | 手打 JSON | 沒有時間軸編輯器，這是動作做不細的最大瓶頸 |
| 角色差異 | 只能依體型分組，或用 `TRACK_SCALE` 調幅度 | 某個角色不能有自己的走路方式 |
| 美術 | `tools/artgen` 用 Python 畫 SVG，美術就是程式 | 畫師沒辦法改；細節有上限；沒有可以交給 AI 或畫師的規格 |
| 聲音 | 只讀麥克風**音量峰值**（`AudioWatch`，Windows 音量表） | 拿不到聲音樣本，算不出音調、母音 |

## 執行原則

- **一步一個檔案**，每步做完停下來審閱
- **兩邊同步**：動畫、繪製、資料格式、聲音分析的每個 Godot 步驟都有對應的網頁步驟，表格裡成對列出；同一個功能兩邊都做完、共用測試通過，才算完成。`Platform/` 底下的系統整合是 Godot 專屬
- **新欄位都是選配**：沒有新欄位的角色、自訂角色、四足型態照舊運作
- **參數放 `data/`，不寫在程式裡**：兩邊讀同一份
- **新功能做成模組**：照 `docs/ARCHITECTURE.md` 的分層與模組規則，不直接塞進 `Main`；動到某個舊功能時，順便把它搬成模組
- **角色座標放角色資料**：嘴巴、眼睛、名牌、道具位置都是角色資料（錨點），不寫在程式裡
- **物理骨不參與 `Probe`**：排球判定只算關鍵影格
- **每個階段前後都錄影比較、量效能**：1、8（客人預設上限）、20 隻（上限）

### 核心想法：程式只認「部件包」

不管圖是怎麼來的，最後都交出同一種東西：

```
art_src/<角色>/                原始檔（畫師或 AI 流程的產出），用 Git LFS
  ├── <角色>.psd / .ora / .kra   分層檔（人工常用）
  ├── parts/*.png                或：一個部件一張透明 PNG（AI 流程常用，任何工具都能產生）
  ├── reference/                 設定圖、表情表、AI 用的參考圖與提示詞（選配）
  └── CREDITS.md                 作者、工具、授權；AI 輔助要寫用了什麼工具、哪些部分人工修過
art/characters/<角色>/          執行用：character.json ＋ 部件圖（由匯入工具或編輯器產生，不手改）
tools/artgen/                   佔位角色產生器，輸出同樣的格式
```

正式角色、自訂角色、佔位角色都是**同一種格式**，桌寵和網頁只認這一種。部件的檔名（或圖層名）就是插槽名，照 `ART_GUIDE.md` 的清單。

### 三種來源，同一條路

| 來源 | 怎麼做 | 匯入方式 |
|---|---|---|
| 純人工 | 在 Krita／Photoshop／CSP 分層畫，圖層用插槽名命名 | 存 `.ora`／`.psd` → `import_layers.py` |
| AI 輔助 | 先做（或產生）角色設定圖與表情表 → 依部件清單逐一產生或從整張圖切出部件 → 補畫被遮住的地方（關節重疊、脖子、手臂內側）→ 統一線條粗細與色調 → 去背 | 存成 `parts/*.png` → `import_layers.py`（資料夾模式），或拖進編輯器 |
| 混合 | AI 出草稿或配色，人工描線、修細節 | 兩種都可以 |

AI 產生的圖常見問題，規格和檢查工具都要能抓出來：同一角色不同部件畫風不一致、關節處沒有多畫重疊、背景沒去乾淨（半透明殘邊）、左右手不對稱、表情之間臉型跑掉。

| 5n | 打通流程（**Chouma 測試部件包**） | 用 5d' 的測試部件包走完「匯入 → 檢查 → 綁骨 → 播放」，桌寵和網頁都要能顯示；確認替換圖片後重新匯入就生效 |

畫師的流程：改 `art_src/` 的分層檔或部件圖 → 匯入（或拖進編輯器）→ 看檢查報告 → 在網頁上看到動起來的樣子 → 需要調整就在編輯器拖拉，不用碰程式。

完成標準：只用繪圖軟體（或 AI 工具）＋網頁編輯器就能更新或新增一個角色；同一個角色的人工版和 AI 輔助版都能用同一條流程匯入；**全部 5 個角色都換成新美術**，在 4K 300% 下清楚、所有動作正常、配件與吉他位置正確；之後功能要用的部件（分層臉、頭髮分節、正面半身）都已經產出並保留在格式裡；記憶體用量實測可接受（含 8 隻客人角色）。

## 第 6 階段：半身 VTuber 模式

放大顯示角色的上半身，像 VTuber 一樣：跟著使用者講話動嘴、依音量與音調換表情或做動作、眼睛跟著游標。**顯示在桌面上**（現有的透明桌面視窗裡），直播時直接擷取整個桌面畫面就會一起播出去。

### 做法：先用現有角色做出可用版，再升級

| 版本 | 美術 | 能做到 | 需要的前置 |
|---|---|---|---|
| **6-A 可用版** | 角色直接放大取上半身（第 5 階段後是新美術） | 依音量動嘴、依音量／音調換表情、做動作（揮手、比 YA、歡呼…）、頭轉向游標、呼吸 | 第 0 階段（0q 仲裁、0r 驅動、0t 聲音介面、0u 掛件）、第 1 階段的疊加層（1k） |
| **6-B 精緻版** | 分層表情、瞳孔、頭髮骨鏈、視差 | 母音嘴型、瞳孔跟游標、眨眼、頭髮飄動、轉頭立體感 | 第 3 階段 |
| **6-C 正面專用美術**（選配） | 角色可以多一套「正面半身」部件（`views.bust`），走第 5 階段的部件包流程 | 正面看鏡頭的 VTuber 構圖（現有角色是側面全身，正面半身更自然）；AI 產生正面半身圖相對容易 | 第 5 階段 |

## 風險與注意事項

| 風險 | 對策 |
|---|---|
| 兩邊程式不一致 | 每個功能都有共用測試（有容許誤差、只測確定的計算）；兩邊都通過才算完成 |
| 網頁從 SVG 換 PixiJS 範圍大 | 4b 單獨一步，先求畫面完全不變，再加網格 |
| 功能模組化搬家時改壞行為 | 隨功能搬、搬家和改功能分開 commit，搬完跑測試與手動確認 |
| 物理參數難調，容易抖或爆掉 | 固定子步進、限制角度、瞬間移動時重設（1d 列出的情況）；編輯器即時調整 |
| 角色專屬動作越來越多、難以管理 | 優先用 `extends` 寫差異；編輯器顯示來源層；`validate.py` 檢查引用 |
| 自訂角色是複製範本 rig | 新欄位全部選配；統一格式時保留舊格式的讀取 |
| 客人角色多隻同時跑，負擔增加 | 每階段量 1、8、20 隻；必要時客人角色降低網格密度或關掉物理；貼圖維持全域快取 |
| `serve.py` 存檔 API 被外部存取 | 只綁 127.0.0.1，存檔前檢查格式與路徑（不能寫出專案資料夾） |
| 四足型態骨骼意義不同 | 物理、網格參數寫在各型態自己的設定 |
| AI 產生的部件畫風不一致、關節沒有重疊 | `ART_GUIDE.md` 規定部件姿勢與重疊；`art_check.py` 抓問題；組裝預覽播放全部動作找穿幫 |
| 正式美術的來源與權利 | 委託畫師要確認著作權歸屬；AI 輔助的素材在 `CREDITS.md` 記錄工具與人工修改範圍，上架 Steam 時需揭露；確認所用 AI 工具的商用條款 |
| 手繪／高解析 PNG 佔記憶體 | 縮小後才放進記憶體，不保留原圖；半身模式的大尺寸貼圖只在開啟時產生 |
| 麥克風隱私 | 只在使用者開啟時才開麥克風；樣本只在記憶體分析，不錄音、不存檔、不傳出去；開著時系統匣有提示 |
| 噪音、別人的聲音、音樂誤觸發 | 噪音門檻＋校正；音調用相對值；規則有持續時間與冷卻時間；設定頁即時顯示數值方便調整 |
| 側面全身角色放大成半身不像 VTuber | 6-A 先求能用；正面半身部件在第 5 階段就跟著 AI 產出，6-C 再接上 |
| 直播擷取桌面時角色被自動隱藏 | 全螢幕自動隱藏對半身模式可以另外關掉（6p）；擷取整個螢幕會包含透明視窗，不需要另外設定 |
| AI 先產出、之後才用到的部件，到時候發現不合用 | 0p 讓格式保留這些部件；5j 組裝預覽先用靜態方式檢查分層臉、頭髮分節能不能對齊；真的不合用只重產那幾個部件 |
| Discord RPC 不是穩定的公開 API | 2026-10-31 已因 `redirect_uri` 規則改了兩次；保留假伺服器測試（0l）；上架 Steam 不能要每個使用者自己建應用程式，要另外找做法（見 `PLAN.md`） |

## 已決定（2026-11-07）

- 美術：**先用 AI 把全部角色快速做出來**，之後視需要人工精修
- 半身模式：**在桌面上看**，直播時擷取整個桌面；**放在最後做**
- 預留：只為已規劃的功能預留接縫（第 0 階段 0p～0v）
- **先用測試部件包把流程打通**：由現有佔位角色自動輸出成新規格的部件包（5d'），用它走完「匯入 → 檢查 → 綁骨 → 播放」；之後換成 AI 或手繪的精細圖，只要照 `ART_GUIDE_AI.md` 替換 `art_src/<角色>/parts/` 的圖再重新匯入，程式不用改
- AI 工具建議（不綁定）：以參考圖編輯、角色一致性好的主流模型為主，例如 ChatGPT 的 GPT Image、Google Gemini 的 Nano Banana、Flux；不用「精靈圖表（sprite sheet）」類工具（那是逐格動畫，我們是骨架動畫，要的是分開的部件）。開始產圖前確認該工具的商用條款
- 其他照建議：試做角色——美術流程與半身用 Chouma，物理用 TK-01＋Sera

## 順序

```
0（必要整理＋預留與解耦）
```

- 第 2 階段之後做動作不用再手打 JSON
- 半身模式放最後：那時分層臉、瞳孔、頭髮物理、正面半身部件都已經有了，6-A 到 6-C 可以一路做完
